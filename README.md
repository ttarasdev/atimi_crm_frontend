# Atimi CRM frontend

CRM Atlantis для легалізації, на основі Ivan CRM. Польський адаптивний інтерфейс, Next.js App Router, TypeScript strict, SCSS Modules і TanStack Query.

## Запуск

Node 24.20.0, npm 12.0.2.

```sh
npm ci
cp .env.example .env.local
npm run dev
```

Фронт: http://localhost:4200. API: http://localhost:4201. Публічну production адресу API задає `NEXT_PUBLIC_API_URL` під час збірки (`https://atimi.pl/api` для підготовленого reverse proxy). Домен CRM — `atimi.pl`. Секрети БД, SMTP та JWT залишаються лише на сервері.

## Доступ

- Admin: повний доступ.
- Manager: змінює своїх клієнтів, переглядає неприватних клієнтів інших працівників; без загальної аналітики та адміністративних змін.
- Sender: незалежне право на розсилки. Одиночна пошта зі спільних налаштованих скриньок доступна всім працівникам. Можна створити працівника лише з цією роллю. При створенні за замовчуванням вибрані Manager та Sender.

Нові клієнти приватні. Відповідальний і адмін можуть змінити приватність; неприватні справи й документи доступні іншим менеджерам для читання. Усі обмеження додатково перевіряє API.

## Можливості

- Клієнти, контакти, особисті дані, адреси, PESEL, громадянство, побит, робота та навчання.
- Окремі згоди на маркетингові та автоматичні повідомлення клієнтам. Маркетингові розсилки охоплюють лише клієнтів із emailMarketingConsent=true.
- Системний каталог карт документів і статусів, строки чинності та нагадування за 3/2/1 місяць. Сервер створює події в календарі відповідального. Адмін задає дефолтні строки, час Europe/Warsaw і додатковий email.
- Цифровий портфель: 13 окремих дизайнів карт побиту, резидента, візи, паспорта та інших документів. Дані особи беруться з профілю; форма має живий preview, конструктор — той самий візуальний каталог. Поточний документ побиту менеджер позначає явно; строк, замінені й архівні записи відображаються окремо.
- Сімейні зв'язки між окремими клієнтами з урахуванням приватності, неблокувальні попередження про дублікати та історія змін.
- Справи, етапи, задачі, нотатки, документи та шаблони цілої справи з порядком етапів. Копії незалежні від наступних змін шаблонів.
- Календар, особисті нотатки, працівники, бібліотека, DOCX-шаблони та генерація документів.
- SMTP-пошта, збережені заготовки, історія відправлень. `/main/mail` доступна всім працівникам, `/main/mail/campaigns` — розсилки для admin/sender: фільтри як у клієнтах, попередній перегляд одержувачів, окремі листи кожному, негайна або запланована відправка Europe/Warsaw, стан доставки й скасування очікування. Manager без sender не відкриває кампанії. Admin має всю неархівну аудиторію, решта — лише клієнтів із власним managerId; sender-only не отримує доступу до чужої бази. Джерела та етапи для фільтрів завантажуються через окремий пагінований `/mail-campaigns/filter-options`, список опікунів — тільки для admin. Inbox відсутній.
- Звернення з сайту, партнери, налаштування компанії та контенту сайту, пульпіт і аналітика адміністратора.

Розділ нерухомостей прибраний. `/main/tasks` — єдиний список внутрішніх і клієнтських завдань через `/tasks`: вкладки сьогодні/прострочені/найближчі/без терміну/виконані/усі, пошук, стан, пріоритет і пагінація. Admin перемикає команда/мої, фільтрує та призначає активних працівників; інші працюють зі своїми. Sender-only має власні внутрішні завдання без клієнтської бази. Форма підтримує опис, відповідального, стан, пріоритет, дату й необов’язковий час Europe/Warsaw та явну прив’язку до доступного клієнта/етапу. Та сама задача відображається в календарі, без дубля дедлайну. Зустрічі, тижневі задачі й серії відкриваються для читання з переходом у календар. Старі терміни зберігає backend-міграція 038. Активний список оновлюється щохвилини; мутації узгоджують кеш задач, етапів, календаря й огляду.

## Перевірки

```sh
npm run lint
npm run typecheck
npm run format:check
npm run build
npx playwright test tests/atimi.spec.ts
```

`tests/atimi.spec.ts` перевіряє desktop/mobile з підміненими API: приватність, read-only чужого клієнта, дані легалізації та згоди, картки документів, сімейні зв'язки, створення справи із шаблону та Sender. Тести не змінюють робочу БД і не надсилають листів. Успадковані тести Ivan адаптовано для спільних функцій, портів, сесії Atimi та нових контрактів. QA знімки — `/tmp/atimi-frontend-shots`.

## Початковий екран

Заставка автоматично переходить до входу або CRM приблизно за секунду. Перехід запускається серверним inline-script до готовності React; клієнтський fallback підтримує навігацію всередині застосунку. Повільні або недоступні початкові JS-файли не залишають користувача на заставці. Ключ localStorage спільний із API auth-token; якщо сховище недоступне, відкривається форма входу. Регресії: `npx playwright test tests/intro-navigation.spec.ts tests/auth.spec.ts` (desktop/mobile, без реальних API чи листів).

Для розсилок застосуйте міграцію backend `031-mail-campaigns.cjs`. Worker перевіряє чергу кожні 30 секунд; `MAIL_CAMPAIGNS_ENABLED=false` призупиняє доставку на сервері. Одержувачі фіксуються при створенні, згода та доступ перевіряються повторно перед доставкою. Повтор після мережевої помилки використовує ту саму спробу створення; непідтверджені SMTP-результати не надсилаються повторно автоматично. Вкладення обираються з бібліотеки. `tests/mail-campaigns.spec.ts` перевіряє фільтри, термін Warsaw, скасування, ролі та повтор після помилки з mock API на desktop/mobile.

Картка «Płatność» праворуч у клієнта містить загальну суму, валюту (PLN за замовчуванням), статус і коментар. «Nieopłacone» — червоний, «Częściowo opłacone» — жовтий, «Opłacone» — зелений. На mobile картка переходить у спільну колонку над справами. Admin або власник заповнює її вручну через PATCH клієнта; для чужих спільних/архівних клієнтів доступний перегляд. Список клієнтів має серверний фільтр оплати. Аналітика доступна лише admin, показує кількість за статусами й суми окремо за валютами. Частково оплачені суми виділяються окремо: коментар не використовується для автоматичного розрахунку залишку. Потрібна міграція backend 034.

Перемикач участі в розсилках на сторінці клієнта змінює наявну маркетингову згоду профілю легалізації. Вимкнення враховується перед надсиланням у запланованій кампанії. Увімкнення дозволяє вибрати клієнта для наступної кампанії, але не змінює стару зафіксовану аудиторію.

Запити документів дозволяють створити запис без файла й скопіювати тимчасове посилання для клієнта. Клієнт відкриває `/upload-document#...` без облікового запису та завантажує один файл. Після успіху документ з’являється у CRM, відповідальний отримує сповіщення в дзвіночку. Посилання можна відкликати або замінити, строк дії стандартно 7 днів. Токен не передається в URL API; публічна сторінка не відкриває інші дані клієнта або файли. Потрібна міграція backend 033.

Пошук у шапці CRM об’єднує доступні клієнти, справи, етапи, документи, нотатки, ліди, партнерів, шаблони й розділи застосунку. Admin також шукає працівників. Після введення є затримка 300 мс, попередній запит скасовується; групи мають по три результати й кнопку розгортання з пагінацією. На mobile вікно займає весь екран. Результат відкриває конкретний запис, зокрема поза першою сторінкою списку; закриття прибирає query, щоб його можна було відкрити повторно. Sender-only пошук недоступний. Перевірки: `tests/global-search.spec.ts`, `tests/search-deep-links.spec.ts`.

У нотатках клієнта та етапу введення `@` відкриває пошук працівників, які вже мають доступ до клієнта. Вибір працює клавіатурою й натисканням, позначені адресати передаються окремими ID разом із текстом. Нові згадки створюють сповіщення в спільному дзвіночку та ведуть до конкретної нотатки. Згадка не надає доступу й не надсилає email. Повторне додавання адресата в ту саму нотатку не дублює сповіщення; видалена або недоступна нотатка показує стан помилки. Потрібна міграція backend 036. Перевірки: `tests/note-mentions.spec.ts` та документні регресії `tests/document-upload-public.spec.ts`.

Календар має три розклади: зустріч із часом, задачу на конкретний день без часу та задачу на весь тиждень без вибору дня. Тижневі задачі показані окремим блоком у режимах дня, тижня й списку, підтримують виконання, редагування та щотижневе повторення. Прострочення настає після неділі за Europe/Warsaw; SMTP-нагадувань для них немає. Admin може відкрити календар працівника з його профілю й створити будь-який із трьох записів. Передача окремого клієнта іншому менеджеру залишається у формі клієнта, поточні й майбутні тижневі задачі переносить сервер. Потрібна міграція backend 035. Перевірки: `tests/calendar.spec.ts`.

Розсилки пропонують лише `app@atlantis.info.pl`; contact/gmail доступні для одиночних листів. Сервер перевіряє фактичні SMTP-логін та From при preview/create і перед доставкою, тому сама зміна назви скриньки не відкриває її для кампанії. У нового клієнта участь у розсилках стандартно увімкнена; наявний перемикач та форма легалізації можуть її вимкнути. Автоматична пошта не вмикається. Старі явні відмови зберігаються; перед оновленим backend потрібна `037-marketing-default.cjs`.

У звичайній пошті, клієнтському composer і кампаніях один класичний дизайн доступний польською, англійською та українською. Вибір мови зберігає ручний текст і вибраний preset; порожній preview використовує локалізований приклад каталогу про справу клієнта. Дані профілю та компанії не перекладаються. Старі посилання на оформлення відкривають польську версію, мовні фото-посилання — відповідну мову без фото. Backend оновлюється разом із frontend; нова міграція не потрібна.

Внутрішній код української мови та API — `ua` (клієнти, звернення, ключі translations, поштові template ID/language). Старі поштові URL `uk`/`uk-*` відкривають український шаблон і надсилають canonical `ua`. Для стандартного HTML lang та Intl використовуємо явне відображення `ua` → `uk`.
